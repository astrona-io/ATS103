# ATS103 — Replication, P2P Preheating & Remote Registries (Harbor)

Course material for the **Replication, P2P Preheating & Remote Registries**
domain of the Astrona Harbor training path
([ATP020](https://github.com/astrona-io/ATP020)), which is **15% of the
path**. Written for **Harbor 2.15.4** and the **Harbor CLI v0.0.27**.

> **Status: draft, not yet run.** Every page, playground and lab was written
> from the Harbor 2.15 and Dragonfly documentation. None has been started on a
> cluster, and no lab has passed `astrona test` yet. See `CLAUDE.md` for the
> facts to check first.

The course opens with an Introduction in `sections/intro/` (welcome, machine setup,
how the course is made). Everything else lives under `sections/`. Each section
contains:

- **Modules** — a reading chapter split into a short landing page, ordered
  deep-dive parts and a summary page, a throwaway **playground** to explore in,
  and a graded **lab** placed right after the part it tests.
- **A capstone** — one larger graded lab combining that section's module into a
  single scenario with several independent faults.

Harbor from a public registry on demand. Section 030 sends them on to the
nodes that will run them, through a peer-to-peer engine.

## The lab environment

Every playground and lab is a **kind** cluster with:

- **Harbor 2.15.4** (chart `harbor-helm` 1.19.4, installed with Helm 3.22.1)
  at `https://harbor.localtest.me:8443`, with a TLS certificate generated by
  the chart. Lab-only administrator `admin` / `Harbor12345`.
- the **`workstation`** pod with `harbor`, `regctl`, `oras`, `cosign`, `curl`
  and `jq`, trusting Harbor's CA. Every Harbor command runs there.
- the **`mirror`**, a CNCF Distribution registry (`registry:3.1.2`) on plain
  HTTP at `http://mirror.localtest.me:5001`, as the remote registry.
- the project **`inventory`** with `inventory/podinfo` (tags `6.15.0` and
  `v1.0.0`).
- in section 030 only, a minimal **Dragonfly 2.5.2** (manager, scheduler, one
  seed peer, MySQL, Redis). Section 030 environments need about 6 GiB.

Both names resolve inside the cluster through CoreDNS `rewrite stop` blocks;
the web portal is reached from the machine with
`kubectl -n harbor port-forward svc/harbor 8443:8443`.

## Running a playground

```bash
astrona run --git ssh://git@github.com/astrona-io/ATS103.git -c sections/<section>/<module>/playground
astrona destroy <name>
```

## Running a lab

Labs and capstones are graded. Read `question.md`, do the work, and submit:

```bash
astrona run --git ssh://git@github.com/astrona-io/ATS103.git -c sections/<section>/<module>/labs/lab-01
astrona submit -c sections/<section>/<module>/labs/lab-01
astrona destroy <name>
```

Each lab grades the **final state of Harbor** with independent checks, and
several of them push their own test artifacts: a release tag that must reach
the mirror, a development tag that must not, and a deleted release that must
disappear from it.
